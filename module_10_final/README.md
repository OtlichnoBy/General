# Рекомендательная система для e-commerce

Дипломный проект 2-го года обучения DS/ML в Skillfactory (трек ML-инженер). Максимум баллов — 25/25 от ментора.

## О проекте

Имитация реальной работы junior ML-инженера в команде, создающей рекомендательную систему для e-commerce ритейлера. Бизнес-задача — повысить допродажи на 20% через персонализированные рекомендации на главной странице магазина (3 слота).

**Целевая метрика:** Precision@3 (точность топ-3 рекомендаций)
**Baseline:** 0.61% (рекомендация популярных товаров)

## Данные

- **1 407 580** уникальных посетителей

## Модели и результаты

| Модель | Precision@3 (val) | Precision@3 (test) | Примечание |
|--------|-------------------|---------------------|------------|
| Baseline (топ-3 товаров) | 0.61% | 0.61% | По числу транзакций до 01.07 |
| NMF | 0.41% | 0.13% | n_components=25 |
| LightFM | 1.52% | 0.15% | Гибридная модель с item features |

### Анализ результатов

Обе модели продемонстрировали классическое переобучение, но в разной степени:

- **LightFM:** падение Precision@3 с 1.52% до 0.15% (в 10 раз). При увеличении регуляризации с 1e-5 до 1e-4 тестовая метрика растёт до 0.3% — признак того, что модель переобучилась на эмбеддингах при 300 компонентах и высокой разреженности данных.
- **NMF:** падение с 0.41% до 0.13% (в 3 раза). Более стабильна благодаря простоте архитектуры.
- **LightFM с 182 706 токенами признаков** показала лишь +0.02 п.п. относительно NMF при 85-кратном увеличении времени обучения.

Основные причины падения метрики на тесте:
1. **Временной сдвиг (Temporal Drift):** поведение пользователей и актуальность товаров изменились между периодами train/validation/test.
2. **Переобучение матрицы эмбеддингов:** 300 латентных факторов при разреженности данных ~0.01% привели к подгонке под паттерны валидационного периода.
3. **Узкий сегмент оценки:** на тесте оценивалось только 225 пользователей с покупками, где попадание в жёсткий Top-3 без переранжирования крайне затруднено.

### Направления для улучшения

- **Двухуровневое ранжирование:** использовать LightFM/NMF для генерации Top-100 кандидатов, а финальный Top-3 ранжировать градиентным бустингом с динамическими признаками.
- **Усиление регуляризации:** подбор `user_alpha` и `item_alpha` в более широком диапазоне для предотвращения переобучения эмбеддингов.
- **Учёт временного затухания:** добавление весов свежести для недавних событий, чтобы снизить влияние Temporal Drift.

## Production (Docker API)

Модель обёрнута в REST API сервис внутри Docker-контейнера:

### Запуск

Docker-образ можно скачать по [ссылке](https://drive.google.com/file/d/1gAbHQy6hymKl04c_zqkH6X6IyRjg9aFi/view?usp=sharing).

```bash
docker load -i recommendation-service.tar
docker run --name recommendation-service -p 8000:8000 recommendation-service
```

### Эндпоинты

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/health` | Проверка состояния сервиса и модели |
| GET | `/metrics` | Параметры модели и данные обучения |
| POST | `/recommend` | Получение топ-k рекомендаций по `user_id` |

### Пример запроса

```bash
curl -X POST http://localhost:8000/recommend \
  -H "Content-Type: application/json" \
  -d '{"user_id": 64, "k": 3}'
```

Полная документация API с примерами для Linux/macOS/Windows — в [DOCS.md](DOCS.md).
